# ADR-0001：一期桌面技术基线

- 状态：接受，用于 M0 和第一版应用骨架
- 日期：2026-10-11

## 背景

AceMode 需要访问摄像头、麦克风和本地文件，支持长时间录制、分段落盘、异常恢复以及 FFmpeg 后处理。项目首先验证 macOS，同时保留后续支持 Windows 的可能。

## 决策

- 使用 Electron 作为桌面运行时；
- 使用 React 与 TypeScript 构建界面；
- 媒体文件保存在用户明确选择的项目目录；
- 后续使用 SQLite 保存元数据，不在数据库中保存媒体二进制；
- 后续使用 FFmpeg 处理转码、混音、拼接和最终导出；
- 云端 AI、MCP 和 Skill 均通过受控接口接入，不直接修改正式项目状态；
- 第三方编辑先生成隔离提案，用户接受后才创建新的派生资产和版本。

## 理由

Electron 的包体和内存成本较高，但它能降低桌面界面、设备权限、调试、自动更新和跨平台交付的首期集成风险。React 与 TypeScript 也便于共享领域类型，并与现有原型保持较短迁移路径。

## 未解决问题

- 摄像头和麦克风的具体采集方案；
- 分段容器、编码和尾段恢复窗口；
- SQLite 驱动及 schema migration 方案；
- FFmpeg 分发、签名和硬件编码策略；
- 首期 TTS、ASR 与 LLM 服务；
- MCP 本地进程、远程 HTTP 与权限模型的最终支持范围。

这些问题必须通过 M0 技术实验确认，不能仅依赖框架文档或模拟测试。
